# Session Management in Web Security — Lab Website

A small PHP site built for the "Session Management" lab activities: login/dashboard
with a 5-second inactivity timeout, and a Session ID exploration tool.

## Files

| File | Purpose |
|---|---|
| `login.php` | Login form (`admin` / `12345`). Regenerates the Session ID on success. |
| `session_check.php` | Included at the top of every protected page. Verifies login and enforces the 5-second timeout. |
| `dashboard.php` | Protected. Shows session info and links to every other page. |
| `about.php` | Protected. |
| `contact.php` | Protected. |
| `logout.php` | Destroys the session and its cookie, redirects to login. |
| `session_info.php` | Not protected. Shows PHP's session-ID configuration (version, length, bits/char, a generated ID). |
| `session_id_demo.php` | Not protected. Generate/display a Session ID, calculate possible combinations, regenerate the ID, plus on-page instructions for the cookie-editing and cross-browser comparison steps. |
| `index.php` | Redirects to `dashboard.php` or `login.php` depending on login state. |
| `style.css` | Shared styling. |

## Running it

You need PHP installed (no database required).

**Option A — PHP's built-in server**
```bash
cd session_activity
php -S localhost:8000
```
Then visit `http://localhost:8000`.

**Option B — XAMPP / WAMP / MAMP**
Copy the `session_activity` folder into your `htdocs` directory, then visit
`http://localhost/session_activity`.

## Trying the 5-second timeout

1. Log in and land on the Dashboard.
2. Wait more than 5 seconds without loading another protected page.
3. Click "About Us" (or refresh) — you'll be bounced back to `login.php` with a
   timeout message, because `session_check.php` compares `time()` against the
   `last_activity` timestamp stored in `$_SESSION`.

To change the timeout, edit `SESSION_TIMEOUT` at the top of `session_check.php`.

## Trying the Session ID lab (`session_id_demo.php`)

No login needed for this page:

1. **Part 1** — reload the page a few times and watch the Session ID stay the
   same while the reload counter increases.
2. **Part 2** — read off the computed `N = C^L` for your PHP's session
   configuration.
3. **Part 3** — click "Regenerate ID" and compare the old/new IDs shown at the top.
4. **Part 4** — in DevTools, edit the session cookie's value manually, then
   reload and see the server treat you as a new session.
5. **Part 5** — open the same page in a second browser (or incognito window)
   and compare the two Session IDs.
